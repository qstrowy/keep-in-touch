# KeepInTouch landing page brief

Status: implemented and locally verified on `codex/keepintouch-landing`. Public landing, sign-in, and check-email presentation are complete; dashboard redesign is a later step.

## Product and verified context

- KeepInTouch is an existing private relationship memory application. Owners store people and dated interaction notes and can explicitly request Core Topics with supporting conversation questions.
- Sources: `context/foundation/prd.md`, current application code, and inspection of the rendered home page on 2026-11-16.
- The current `/` page is a short introduction with a link to `/auth/signin`. The existing visual style uses a dark background and purple/blue accents; it is not a binding brand requirement.
- The existing sign-in page uses email magic links. Local synthetic demo access is separate from real email authentication.
- Website and interview language: English, following the existing application and this conversation.

## User request and binding requirements

- Use the super-landing-page skill to develop a new landing experience for KeepInTouch.
- The new direction may depart from the current visual style.
- Leading visual material: graphic experiment / collage, selected by the user at Stage 6. Its layers and juxtapositions organize the page. The specific motifs and palette are agent execution decisions recorded in `DESIGN.md`.
- Brand personality: warm and human as the primary trait, supported by playful and unconventional touches, selected by the user at Stage 7. Keep language welcoming and moments recognizable; playful details should support understanding.
- Composition: layered collage as the primary structure, supported by a chapter sequence, selected by the user at Stage 8. Develop connected scenes with controlled overlap and depth, readable content, and intentional mobile arrangements.
- Motion: rhythmic, selected by the user at Stage 10A. Use coordinated shifts, regrouping, reframing, and scale changes across chapters to explain how scattered details become useful context. Preserve natural scrolling, readable content, and an accessible reduced-motion version; fade-ins alone do not satisfy this requirement.
- Memorable moment: a scroll sequence, selected by the user at Stage 10B. Scattered conversation fragments progressively come together into context for a future conversation. This is a visual explanation of the process, not a claim of live model generation or measured relationship outcomes.
- Argument order: familiar situation/problem -> new approach -> KeepInTouch -> sign-in, selected by the user at Stage 9. Help visitors recognize an everyday need before introducing the product; keep the opening concise.
- The landing experience must lead into the existing application. Agent execution decision: retain `/auth/signin` as a separate page and style sign-in and check-email to match the landing page. Preserve the existing email-link endpoint and validation.
- Permitted visual sources: code/SVG graphics and new illustrations/generated imagery only (user: "5+4 only"). No photography, stock assets, or application screenshots as visual material. New illustrations are atmosphere; readable text and moving collage layers are built in code.
- Develop a design language that can later guide an application redesign. The extent and timing of that redesign remain to be established; no full application redesign has been selected in this interview.
- Work on a separate branch to protect the working application. Created `codex/keepintouch-landing` from `main`.
- Preserve existing application behavior, authentication, owner isolation, and data handling. Do not change or publish production services as part of the interview.
- The pre-existing uncommitted change to `AGENTS.md` records startup guidance from this chat; preserve it separately from new design work.

## Agent execution decisions and hypotheses

- Concept: "Little things, held together." Scattered details form the visual material; grouping and realignment explain returning to context before a conversation.
- Implemented palette: warm paper, dark espresso ink, terracotta, muted sage, pale butter, and a small dusty lilac accent. Exact tokens and allowed illustration tones are recorded in `DESIGN.md`.
- Implemented typography: Georgia regular/italic headlines and Arial/Helvetica supporting UI. These are intentional locally available families; no runtime font-service requests.
- Scope: landing, sign-in, and check-email presentation. The dashboard and relationship-management interfaces remain a later redesign step. No new backend, model invocation, analytics, subscriptions, or publication.
- Working audience hypothesis: people who care about personal relationships but have not identified a need for a memory aid. The interview did not establish demographics or research-backed demand.
- New illustrative notes and conversation scenes are fictional and must be identified as such. The animation explains a process; it does not run extraction or pretend to save notes.
